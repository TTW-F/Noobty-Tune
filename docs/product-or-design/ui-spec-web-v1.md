# Noobty Tune Web V1 UI 规格

## 1. 文档目标

定义 `Noobty Tune` Web V1 的页面结构、信息层级、交互反馈、视觉方向与响应式要求，使设计和实现围绕同一套可执行标准推进。

本文件在编写时参考了当前项目安装的专业技能：

- `find-skills`：用于筛选适配当前阶段的技能
- `web-audio-api`：用于约束 Web 音频相关交互与工程边界
- `ui-ux-pro-max`：用于提取结构化 UI/UX、可访问性、触控和响应式建议

其中：

- `web-audio-api` 的建议整体适配度高，已吸收
- `ui-ux-pro-max` 的结构与可访问性建议适用
- `ui-ux-pro-max` 给出的“偏娱乐化、强烈 block 风格”视觉方向不完全适合调音器，因此仅部分采纳

## 2. 设计目标

页面必须做到：

- 用户一眼知道这是吉他调音器
- 用户知道需要麦克风权限且不会感到被突然打断
- 用户能快速理解当前弦是偏高、偏低还是已调准
- 用户在手机上也能顺畅完成全流程
- 页面在等待、失败、弱信号等状态下都能给出清晰反馈

## 3. 产品界面定位

### 推荐界面气质

- 精准
- 清晰
- 可信
- 轻量
- 略带音乐感，但不娱乐化

### 明确避免

- 过度像音乐播放器或流媒体平台
- 花哨背景压过核心调音反馈
- 大量装饰性动效影响可读性
- 把页面做成营销型 landing page，而不是工具型产品

## 4. 设计结论

基于 `ui-ux-pro-max` 的检索结果与项目场景，建议采用下面这组折中方案：

### 采纳的建议

- `Minimal Single Column`
  适合移动端优先、单任务、快速进入主流程的工具型产品

- 高对比浅色背景
  有利于调音状态信息的快速识别

- 触控友好
  主按钮与主要点击区域必须满足移动端点击尺寸要求

- 清晰加载/等待态
  麦克风初始化和权限等待不能是“静默状态”

- 可访问性约束
  可见焦点、足够对比度、减少对动画的依赖

### 不采纳或仅部分采纳的建议

- `Vibrant & Block-based`
  该风格更适合音乐娱乐平台，不适合“校准工具”主任务

- 夸张的大面积装饰图形
  可以保留少量品牌感，但不应干扰中心读数

## 5. 页面结构

V1 建议为单页结构，包含以下区域：

### 5.1 顶部信息区

内容：

- 产品名：`Noobty Tune`
- 一句话说明：例如“在浏览器里快速给吉他调音”
- 简短信任说明：例如“不上传音频，仅在本地处理”

目的：

- 先解决“这是什么”和“会不会录音上传”的顾虑

### 5.2 启动区

内容：

- 主按钮：`开始调音`
- 权限说明文案
- 浏览器兼容或权限失败提示位

要求：

- 不自动弹权限
- 主按钮应是首屏最明确的操作

### 5.3 核心调音区

这是页面最重要区域，优先级最高。

内容：

- 当前目标弦
- 当前识别音
- 中心偏差仪表
- 当前状态文案
- 已调准成功态

要求：

- 屏幕中心优先展示
- 不应被次级说明抢走注意力

### 5.4 标准调弦参考区

内容：

- 六根弦标准音列表
- 当前高亮目标弦

作用：

- 帮助新手建立“弦名 - 音名”映射

### 5.5 辅助提示区

内容：

- 弱信号提示
- 噪声提示
- 权限恢复建议
- 新手说明

要求：

- 只在需要时展示，不长期占据视觉中心

## 6. 核心组件规格

### 6.1 开始按钮

文案：

- `开始调音`

交互要求：

- 默认可点击
- 点击后进入 loading 态
- 异步期间禁用重复点击

移动端要求：

- 点击区域至少满足 `44x44px`
- 按钮上下应保留足够留白，避免误触

### 6.2 偏差仪表

功能：

- 展示当前频率相对目标音的偏差

建议形式：

- 中央指针 / 游标式水平刻度
- 左侧代表偏低
- 右侧代表偏高
- 中间为调准区域

设计原则：

- 一眼看懂方向
- 视觉反馈连续、平滑
- 不依赖颜色作为唯一信息源

### 6.3 状态文本

状态文案必须通俗，不只显示技术术语。

建议：

- `请拨动一根弦`
- `正在监听`
- `信号太弱，请靠近麦克风`
- `环境噪声较大，请在更安静处重试`
- `偏低，请调高`
- `偏高，请调低`
- `已调准`
- `麦克风权限被拒绝`

### 6.4 目标弦列表

建议展示：

- `E2`
- `A2`
- `D3`
- `G3`
- `B3`
- `E4`

状态：

- 默认普通态
- 当前匹配弦高亮
- 已调准弦可用次级成功态表示

### 6.5 权限/异常提示卡片

使用场景：

- 权限拒绝
- 浏览器不支持
- 无麦克风
- 音频初始化失败

要求：

- 提示原因
- 提示下一步
- 不应只显示通用错误词

## 7. 视觉设计规范

### 7.1 视觉方向

建议采用：

- 浅色背景为主
- 蓝色系作为中性主色
- 橙色或暖色系作为 CTA 和注意提示色
- 成功态使用绿色，但仅在关键结果上使用

### 7.2 推荐色板

这部分参考了 `ui-ux-pro-max` 的工具型/仪表盘配色结果，并结合调音器场景做了收敛：

- Primary: `#3B82F6`
- Secondary: `#60A5FA`
- CTA: `#F97316`
- Background: `#F8FAFC`
- Text: `#1E293B`
- Border: `#E2E8F0`
- Success: `#16A34A`
- Warning: `#D97706`
- Error: `#DC2626`

### 7.3 配色使用原则

- 背景和文本必须满足基础可读性对比
- 偏差方向除颜色外，还要有位置和文本提示
- 成功色不要铺满全屏，只用于强化“已调准”

### 7.4 字体建议

`ui-ux-pro-max` 对当前场景给出的更适配结论是：

- `Inter / Inter`

原因：

- 更像精密工具和仪表盘
- 可读性高
- 中英文环境更稳妥

不建议当前阶段使用更强个性的展示字体作为主字体，因为调音器的主任务是读数与反馈，不是品牌陈列。

## 8. 布局与响应式

### 8.1 移动端优先

V1 默认按移动端优先设计，再向桌面扩展。

### 8.2 建议断点

- `375px`
- `768px`
- `1024px`
- `1440px`

### 8.3 移动端布局

- 单列布局
- 核心调音区置于首屏中央
- 目标弦列表可横向或紧凑纵向排列
- 次要说明折叠或缩短

### 8.4 桌面端布局

- 核心调音区仍居中
- 左右可扩展参考说明或调弦列表
- 不建议桌面端因此变成复杂多栏后台式界面

## 9. 交互状态规范

### 9.1 初始状态

页面显示：

- 产品名
- 产品说明
- 开始按钮
- 权限说明

### 9.2 权限请求中

页面显示：

- 按钮 loading
- 简短等待文案，例如“等待麦克风授权”

### 9.3 监听中

页面显示：

- 提示用户拨动一根弦
- 核心仪表处于待输入状态

### 9.4 检测中

页面显示：

- 当前识别音
- 偏差方向
- 仪表连续更新

### 9.5 已调准

页面显示：

- 明显成功状态
- 成功文案
- 仪表停留在中心稳定区域

### 9.6 异常状态

页面显示：

- 错误原因
- 恢复建议

## 10. 动效规范

### 建议保留

- 按钮 hover / press 反馈
- 仪表轻量平滑过渡
- 状态切换淡入淡出

### 建议限制

- 页面级大范围动画
- 高频闪烁
- 过长的加载动画

### 动效时长

参考 `ui-ux-pro-max`：

- 微交互维持在 `150-300ms`

### 无障碍要求

- 必须尊重 `prefers-reduced-motion`

## 11. 无障碍与可用性要求

这部分直接采纳 `ui-ux-pro-max` 的高优先级约束：

- 正文对比度至少满足基本可读性
- 键盘焦点态必须可见
- 图标按钮必须有可理解标签
- 主按钮和主要交互区域满足触控尺寸
- 相邻点击区域至少保留合理间距
- 加载态必须有反馈

## 12. 与 Web Audio 相关的 UI 约束

结合 `web-audio-api` 技能，页面必须遵循：

- 音频初始化只能发生在用户手势之后
- 页面需要显式的开始动作
- 权限被拒绝时必须有恢复路径
- 音频资源在离开页面或停止时应被清理
- 不应让用户误解为系统会自动播放大量音效

## 13. 组件优先级

### P0

- 开始按钮
- 权限状态提示
- 偏差仪表
- 当前弦/当前音/方向反馈
- 已调准状态

### P1

- 调弦参考列表
- 弱信号和噪声提示
- 新手引导说明

### P2

- 更细致的辅助说明
- 更丰富的视觉强化

## 14. 当前 UI 决策结论

本阶段确认如下：

- 页面采用单页、单任务、移动端优先结构
- 视觉风格以“工具型精确感”为主，不走娱乐化音乐 App 路线
- 字体优先使用 `Inter`
- 核心区域以偏差仪表和状态文案为中心
- `find-skills` 找到的 `ui-ux-pro-max` 对结构和可访问性有帮助，已吸收
- 该 skill 的强烈“音乐娱乐平台”风格不适合本产品主任务，已明确放弃
