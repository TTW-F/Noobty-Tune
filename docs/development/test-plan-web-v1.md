# Noobty Tune Web V1 测试计划（基于当前代码实现）

## 1. 文档目标

为 `Noobty Tune` Web V1 提供统一的测试范围、测试维度与验收关注点，且所有测试项均以当前 `src/` 真实实现为依据。

## 2. 当前代码实现快照（事实基线）

事实来源：`src/main.tsx`、`src/app/App.tsx`、`src/features/tuner/model/useTunerPrototype.ts`、`src/lib/audio/*`、`src/lib/music/*`、`src/types/tuner.ts`。

### 2.1 当前已实现

- 浏览器内麦克风授权与音频上下文初始化（`BrowserMicrophoneManager`）。
- 基于 `AnalyserNode` 的时域帧采集（默认 `fftSize=2048`）。
- 基于 YIN 的音高检测（`70Hz-360Hz`，`probabilityThreshold=0.82`，`rmsThreshold=0.008`）。
- 基于滚动窗口的稳定化（`requiredSamples=3`，`centsTolerance=12`，`maxHistory=5`）。
- 自动目标弦匹配（标准六弦 `E2 A2 D3 G3 B3 E4`）。
- 基础 UI 状态反馈：`idle / requesting-permission / permission-denied / listening / unstable / detecting / in-tune / error`。
- 调试读数展示：`frequencyHz`、`note`、`cents`、`target`、`clarity`、`sampleCount`。

### 2.2 当前未实现（测试时不应按“已支持”验收）

- 手动选弦 UI（状态模型支持 `manual`，但页面未提供切换入口）。
- 多调弦方案（alternate tuning）与多乐器。
- 持久化、账号、云端同步能力。
- 音频工作线程（AudioWorklet）链路与更高阶噪声抑制策略。

## 3. 测试目标

- 验证 Web 端调音主流程可用
- 验证标准六弦调音识别稳定性
- 验证异常流程有清晰反馈
- 验证桌面端和移动端基础可用性
- 验证低频、噪声和权限相关风险

## 4. 测试范围

### In Scope

- 页面进入与开始调音流程
- 麦克风权限请求与失败处理
- 六弦标准调弦识别
- 偏高 / 偏低 / 已调准反馈
- 无输入、弱输入、噪声环境下的状态反馈
- 不同浏览器与设备下的基本可用性

### Out of Scope

- 桌面端客户端
- App 客户端
- 多乐器
- alternate tunings
- 账号相关能力

## 5. 测试维度

### 4.1 功能正确性

- 是否能正常进入调音流程
- 是否能识别六根弦的目标音高趋势
- 是否能正确显示方向反馈
- 是否能正确进入“已调准”状态

### 4.2 识别稳定性

- 是否会在单根稳定延音下频繁跳动
- 是否会误判到错误弦
- 是否在低 E 弦上明显不稳

### 4.3 用户体验

- 是否容易理解开始方式
- 是否容易理解页面反馈
- 是否能在失败时知道下一步怎么做

### 4.4 平台兼容性

- 不同浏览器是否能正常申请权限
- 音频初始化是否受平台限制
- 移动端页面是否可读、可操作

## 7. 核心测试场景

### TC-01 首次进入页面

前置条件：

- 用户首次访问页面

预期结果：

- 用户能清楚理解这是吉他调音器
- 页面明确说明需要麦克风权限
- 页面存在清晰的开始入口

### TC-02 权限授权成功

前置条件：

- 浏览器支持麦克风

操作：

- 点击开始调音
- 允许麦克风权限

预期结果：

- 成功进入监听状态
- 页面无卡死或空白状态

### TC-03 权限被拒绝

操作：

- 点击开始调音
- 拒绝麦克风权限

预期结果：

- 页面进入明确的失败状态
- 给出重新授权或检查权限的建议

### TC-04 无麦克风设备

前置条件：

- 设备无可用麦克风或被系统禁用

预期结果：

- 页面给出可理解提示
- 不应持续停留在不明确的加载态

### TC-05 标准六弦识别

操作：

- 分别拨动 `E2 A2 D3 G3 B3 E4`

预期结果：

- 每根弦都能进入合理的检测状态
- 检测结果与最近目标弦总体一致（当前实现为自动最近目标匹配）

### TC-06 低 E 弦重点验证

操作：

- 多次拨动低 E 弦

预期结果：

- 不应持续误判为高八度或其他弦
- 在正常延音下应能稳定收敛

### TC-07 高 E 弦验证

操作：

- 多次拨动高 E 弦

预期结果：

- 检测速度与稳定性达到可用水平

### TC-08 偏低反馈

操作：

- 将目标弦调低后拨弦

预期结果：

- 页面明确提示应调高

### TC-09 偏高反馈

操作：

- 将目标弦调高后拨弦

预期结果：

- 页面明确提示应调低

### TC-10 已调准反馈

操作：

- 将弦调至接近目标并保持稳定拨响

预期结果：

- 页面在稳定条件下显示已调准（当前逻辑同时依赖稳定化与偏差范围）
- 不应闪烁式频繁进出成功状态

### TC-11 环境噪声场景

操作：

- 在中等背景噪声环境中测试

预期结果：

- 如果结果不可靠，页面应提示噪声影响
- 不应高频率输出明显错误结论

### TC-12 弱信号场景

操作：

- 轻拨弦或设备远离琴体

预期结果：

- 页面能提示信号过弱或未检测到稳定输入

### TC-13 快速短拨场景

操作：

- 对同一根弦进行很短的快速拨弦

预期结果：

- 即使无法稳定识别，也应表现为“结果不足以判断”
- 不应输出大量错误音名

### TC-14 连续切换不同弦

操作：

- 快速依次拨动多根弦

预期结果：

- 页面应能跟随变化
- 若来不及稳定识别，也应表现合理，不应卡死

### TC-15 移动端小屏显示

预期结果：

- 主要反馈区域完整可见
- 文案不重叠、不被裁切
- 按钮与主交互区域可点击

## 8. 重点质量指标

当前阶段建议重点观察这些指标：

- 从拨弦到首次反馈的主观延迟
- 从拨弦到稳定反馈的主观延迟
- 低 E 弦识别成功率
- 已调准状态误判率
- 权限失败后的恢复可理解性

注：

现阶段可以先记录主观体验和人工观察结果，后续再逐步量化。

## 9. 缺陷优先级建议

### P0

- 页面无法开始调音
- 权限流程阻塞主流程
- 核心弦无法识别
- 页面反馈方向错误

### P1

- 低频识别明显不稳
- 状态频繁抖动导致无法判断
- 主要移动端设备不可用

### P2

- 文案不够清楚
- 页面布局在部分设备上较拥挤
- 某些异常提示不够友好

## 10. 测试产出建议

每轮验证建议沉淀：

- 测试日期
- 测试设备
- 浏览器版本
- 场景
- 结果
- 录屏或截图
- 问题等级
- 复现方式

## 11. 当前建议的验证顺序

1. `localhost` 下验证基本流程
2. 桌面 Chrome 验证识别稳定性
3. 手机浏览器验证权限与界面
4. 噪声和弱信号场景验证
5. 低 E 弦专项验证
6. 汇总问题后再决定是否要调整算法或架构
