## 3. WBS 原则

- 围绕 V1 核心目标拆解，不为远期功能提前铺太多任务
- 先验证高风险项，再做界面细化
- 每个阶段都应有可观察产出
- 每项任务尽量能映射到文档、代码、测试或验证结果

## 4. 阶段总览

1. 工程初始化

## 10. 建议的任务优先级

### P0

- 麦克风权限流程
- 音频链路可用
- 检测算法有效
- 偏高/偏低/已调准反馈正确

### P1

- 稳定化体验
- UI 可理解性
- 移动端可用性

### P2

- 新手引导优化
- 页面视觉精修
- 更丰富的辅助提示

## 11. 建议的里程碑

### M1：原型可跑通

定义：

- 可以采集麦克风
- 可以输出频率或音名结果

### M2：核心调音闭环成立

定义：

- 可以完成标准六弦的基础调音流程
- 可以给出明确方向反馈

### M3：Web V1 可用

定义：

- 手机和桌面浏览器都能完成主流程
- 异常场景有明确反馈

### M4：Web V1 可发布

定义：

- 核心缺陷关闭
- 测试计划主要场景通过

## 12. 当前最值得先做的任务

若要立刻进入实现，建议按这个顺序开工：

1. 真实设备验证并沉淀记录（低 E -> 高 E）
2. 完成 `YIN` 与自动相关法对照结论
3. 基于实测回调阈值与稳定化参数
4. 补手动选弦/目标锁定的交互方案
5. 建立最小自动化回归用例
