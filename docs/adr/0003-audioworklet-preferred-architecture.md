# ADR 0003: 正式实现优先采用 AudioWorklet 架构

## 状态

Accepted

## 背景

Web Audio 处理可以采用更轻量的快速验证方式，也可以采用更正式的 `AudioWorklet` 方案。

对于调音器来说，音频处理链路需要尽量避免：

- 主线程卡顿影响识别
- UI 渲染与音频处理互相干扰
- 后续在性能和稳定性上返工

当前已知工程约束表明：

- 音频上下文需要用户手势触发
- 重 DSP 更适合脱离主线程的音频处理模型

## 决策

方案分两步：

- 原型验证阶段允许采用更轻量的方式快速验证算法
- 正式实现阶段优先采用 `AudioWorklet` 组织持续音频处理

## 原因

- 保留原型阶段快速试错能力
- 避免主线程负载直接影响识别体验
- 为后续稳定性优化留出更好架构基础

## 影响

正面影响：

- 架构更适合实时音频处理
- 更利于后续性能优化
- 更利于保持 UI 与检测解耦

负面影响：

- 初始实现复杂度更高
- 调试难度略高于简单方案

## 后续

- 原型验证阶段重点确认算法效果
- 一旦进入正式实现，尽早完成 `AudioWorklet` 接入
