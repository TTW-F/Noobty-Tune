# ADR 0004: YIN 作为 Web V1 默认音高检测候选路线

## 状态

Accepted

## 背景

浏览器端单音音高检测常见方案包括：

- 自动相关法
- `YIN`
- 更复杂或更底层的原生 / `WASM` 方案

当前项目阶段需要的是：

- 先有一条默认技术路线
- 但不把未来优化空间封死

## 决策

Web V1 默认将 `YIN` 作为优先验证和优先实现的候选路线。

自动相关法保留为：

- 对照原型方案
- 兜底实验方案

## 原因

- `YIN` 在单音基频检测中通常在准确率和速度之间更平衡
- 相比完全自研更复杂方案，上手成本适中
- 有利于尽快验证低 E 到高 E 的整体表现

## 影响

正面影响：

- 技术路线明确
- 降低方案讨论反复横跳

负面影响：

- 仍需额外稳定化和异常值过滤
- 若实际设备测试表现不佳，仍需调整实现

## 后续

- 对低 E、高 E、弱信号、噪声场景做专项验证
- 若纯前端 `YIN` 无法满足要求，再评估 `WASM` 或其他实现
