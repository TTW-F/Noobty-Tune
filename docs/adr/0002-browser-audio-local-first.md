# ADR 0002: Web V1 采用浏览器本地音频处理

## 状态

Accepted

## 背景

Web 端调音器的核心任务是实时处理麦克风输入并给出低延迟反馈。

如果把音频上传到服务端处理，会引入：

- 网络延迟
- 音频上传等待
- 隐私顾虑
- 更高的实现复杂度
- 更高的基础设施成本

对于 V1 来说，这些成本与收益不匹配。

## 决策

Web V1 采用浏览器本地音频处理：

- 使用浏览器麦克风获取音频流
- 在前端完成音频分析和音高检测
- 不上传原始音频到服务端

## 原因

- 调音任务对实时性要求高
- 本地处理更符合用户对隐私的预期
- 首版无需引入后端音频处理架构
- 后续桌面端和 App 也更容易复用同一套核心逻辑

## 影响

正面影响：

- 更低延迟
- 更简单的系统边界
- 更低运营复杂度

负面影响：

- 需要更关注浏览器兼容性
- 算法性能受前端运行环境约束

## 后续

- 若未来有更复杂分析需求，再单独评估服务端或混合方案
