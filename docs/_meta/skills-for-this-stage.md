# 当前阶段需要的 Skills 结论

我们的目标不是“为了装 skill 而装 skill”，而是让项目前期更快形成可开发输入。

基于当前项目状态：

- 产品方向已明确：`guitar tuner`
- 当前平台已明确：`Web`
- 关键风险也明确：音频权限、低频识别稳定性、交互可理解性

所以这阶段真正值得保留或补充的 skill 只有少量几个：

## 已安装

- `find-skills`
  用途：后续按需找能力，不需要频繁使用，也不应该主导项目。

## 建议保留为核心候选

- `requirements-analysis`
  用途：把产品目标、用户场景、V1 范围、非目标、验收标准整理清楚。

- `system-design`
  用途：把浏览器音频链路、算法选择、状态机、模块边界落下来。

## 现在不急着装

- 大而全的设计流程包
- 泛文档模板 skill
- 与当前问题无关的部署、增长、营销类 skill

判断标准只有一个：

如果某个 skill 不能直接帮助我们把下面这些东西产出来，就先不需要：

- 可执行的 V1 范围
- 可实现的技术方案
- 可验证的验收标准
- 可继续扩展到桌面端和 App 的架构边界
